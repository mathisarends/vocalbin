# TTFA measurements — 2026-10-29

This is one local Windows measurement session, not a general provider ranking. All requests succeeded. Credentials were loaded with `load_dotenv` without printing them. No credentials, voice UUIDs, or absolute model paths are included in this report or its CSV.

## Complete text

Text: `Hello! This is a first-audio latency benchmark.` Each provider has 10 cold and 10 warm samples, with one excluded warm-up request before the warm samples. Cold means a newly constructed client/service; warm means one reused service, explicitly preconnected for Cartesia and Deepgram. It does not control remote server cache state. All output is raw PCM.

| Provider / model | Cold median TTFA | Warm median TTFA | Warm p95 TTFA | Cold median setup |
| --- | ---: | ---: | ---: | ---: |
| openai: gpt-4o-mini-tts / marin | 725.3 ms | 513.4 ms | 659.5 ms | 13.2 ms |
| cartesia: sonic-3.5 / configured voice | 182.7 ms | 70.4 ms | 75.4 ms | 12.9 ms |
| deepgram: aura-2-thalia-en | 485.4 ms | 147.6 ms | 164.7 ms | 27.5 ms |
| piper: de_DE-thorsten-medium.onnx | 83.3 ms | 64.5 ms | 100.6 ms | 2626.3 ms |

TTFA begins when stream consumption starts. Client construction and Piper model loading are excluded from TTFA and reported separately as setup. In particular, Piper's low TTFA requires an already-loaded voice; constructing a fresh voice adds seconds on this machine. Warm-up/preconnection is outside the warm TTFA samples.

Piper used the configured German medium-quality voice at 22,050 Hz with the same English test text. The remote voices and quality settings differ. This comparison says nothing about perceptual voice quality. Cartesia used the voice configured in the local environment; its UUID is intentionally omitted.

## Incremental text

The source makes `Hello! ` available first, then `This is a first-audio latency benchmark.` 300 ms later. Text production runs concurrently with connection setup. Each configuration has 10 measured warm requests after one excluded warm-up.

| Provider | Configuration | Median TTFA | p95 TTFA |
| --- | --- | ---: | ---: |
| deepgram | flush_on=end | 144.6 ms | 150.3 ms |
| deepgram | flush_on=first_chunk | 189.7 ms | 207.9 ms |
| cartesia | max_buffer_delay_ms=0 | 71.3 ms | 111.0 ms |
| cartesia | max_buffer_delay_ms=100 | 68.1 ms | 71.2 ms |

Deepgram already returned audio before the second phrase arrived with `flush_on="end"`. Early flushing did not improve TTFA in this scenario and had a higher median. Keep the existing `end` policy for this complete-phrase pattern; test early flushing separately for other input patterns rather than assuming a benefit.

Cartesia's 0 and 100 ms buffer settings had similar median TTFA in this scenario. The 100 ms setting did not add a fixed 100 ms delay here. Do not select a buffer value from this test alone without checking speech naturalness and more varied text.

## Measurement limits and reproduction

- These are first non-empty audio bytes at the Python iterator, not first audible sound. Playback, decoder, forwarding and device buffers are excluded.
- With only 10 samples, nearest-rank p95 is the largest observed sample, not a stable tail-latency estimate.
- Profiles ran sequentially rather than interleaved. Provider load, network conditions and local machine activity may differ between profiles.
- Deepgram requests were spaced outside the timed request according to the expected flush count to avoid ordinary runs exhausting the rolling flush budget. Warm-up calls are excluded from statistics.
- A benchmark reference-retention bug was found while measuring Piper. The previous Piper series was excluded and repeated after fixing it; the discarded samples are absent from this CSV.
- The currently loaded API keys were not found in the currently tracked files. The `.env` file is ignored and untracked. This was not a full Git-history secret audit.

Use [the latency guide](../latency.md) and [the benchmark script](../../scripts/benchmark_tts.py) to repeat the runs. Set the same model/voice and text explicitly for comparisons. The benchmark makes billable requests for remote providers. [All 120 measured samples](2026-10-29-ttfa.csv) are included without secrets.

Commands for the two Deepgram input strategies:

```console
uv run --extra deepgram python scripts/benchmark_tts.py --provider deepgram --mode warm --runs 10 --text-chunks "Hello! " "This is a first-audio latency benchmark." --chunk-delay-ms 300 --flush-on end
uv run --extra deepgram python scripts/benchmark_tts.py --provider deepgram --mode warm --runs 10 --text-chunks "Hello! " "This is a first-audio latency benchmark." --chunk-delay-ms 300 --flush-on first_chunk
```
